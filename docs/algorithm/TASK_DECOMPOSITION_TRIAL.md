# 任务拆分试验

本轮借鉴 TDAG 的结果驱动更新，以及 MegaAgent 的分层拆分与监控思路。
实现保留在既有 LangGraph 中，额外增加一次有上限的模型语义审查。

## 新方案流程

用户条件和可用时间 → 生成阶段与具体任务 → 一次语义审查 → 试排 → 必要时修订任务范围 → 用户核对。

语义审查核对材料是否明确、动作能否独立执行、依赖顺序、连续时长、核心目标和预算。
发现问题时返回一份完整且通过 Schema 校验的修订方案。
无问题时保留原候选。接口异常或结果无法校验时保留初稿，在核对界面显示检查未完成。
预算修订仍限一次，语义审查不递归重试。
内部 quality_review 和 metrics 记录审查状态及调用耗时，界面继续显示自然语言答复与任务列表。

stage 是阶段标签，存储兼容没有该字段的历史方案，任务清单在条目旁展示标签。
当前每份方案仍最多16项，长期目标按当前预算确定本轮范围。

## 对话反馈

模型结合当前任务、完成状态、依赖、用户自述和日程评估局部调整。
补充了错因澄清、前置结果和相关任务更新规则。
已采纳但未完成的任务继续沿原编号提出调整，正式写入沿用已有确认和冲突检查。
这一步仍由模型根据提示判断，尚未增加独立的反馈分类器。

## 验证与边界

离线案例覆盖“听力练习和复盘”拆成诊断卷A作答、卷A错因分析、材料B复测，
以及无效依赖的审查结果回退。原有试排缩减范围和确认修改日程的回归测试继续运行。

真实效果需要用相同模型与用户条件对比，观察材料指代错误、用户修改量、
预算超限情况、响应时间和调用次数。新方案固定增加一次审查调用，可能增加等待时间。
模型审查本身可能判断错误，结构化校验不能证明学习方法有效。
本轮未训练新模型，也未自动写入教学 Skill 经验库。
