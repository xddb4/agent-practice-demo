# StudyPilot 工程缺口的解决方案

## 已在本轮落地

- DeepSeek 模型适配：模型、地址、服务商和视觉开关均由环境配置提供。业务工作流不绑定具体供应商。密钥仅在被Git忽略的本地`.env`中。
- 严格候选契约：日程、课表、证据、推荐分别采用Pydantic模型，禁止额外字段，校验枚举、整数范围、完整起止时间、时区、教学周与完成标准。
- 模型JSON模式 + 后端校验：格式失败最多修复一次，仍失败则拒绝返回候选。用户修改候选后，通过`/api/agent/{id}/review`再次校验，保留原始候选和修改后版本。
- 已完成三路DeepSeek真实请求与工具调用验证；原型外观布局仍保持兼容方式，不能将模型联调通过等同于全部产品需求完成。

## React 全量迁移

采用保留原型CSS、素材和DOM层级的逐页迁移，而不是重做视觉设计。

1. 提取原型样式和内嵌图片为可复用资源，保留欢迎页、日期画廊、导航和交互设计。
2. 拆分`LoginPage`、`PlanPage`、`MatrixPage`、`ReportPage`、`RecommendationPage`、`PersonalPage`。
3. 拆分Calendar、TaskCard、Timeline、Quadrant、EvidenceInbox、CandidateReview等组件；表单和状态切换改为React事件，移除内联onclick及全局变量。
4. 用共享的任务查询状态驱动计划、象限和详情；保存失败保留表单并展示重试，完成/恢复/分类操作使用服务端返回结果同步。
5. 每迁移一页，对照原型进行桌面和窄屏截图回归，并验证键盘、拖动、弹窗和减弱动效设置。全部迁移验收后移除iframe和兼容脚本。

验收：外观遵循用户已确认的最终原型；页面由React组件渲染；不再依赖iframe、全局任务数组或浏览器本地账号。

## PostgreSQL 与领域模型

当前SQLAlchemy的JSON快照适合单用户原型，不能替代最终业务数据模型。

正式改造采用users、tasks、schedule_entries、recurrence_rules、schedule_exceptions、artifacts、evidence、evidence_links、reports、report_evidence、agent_runs、proposals、proposal_adoptions等表。保留现有records数据，通过一次性、可重复的迁移脚本导入；不删除现有用户数据。

- Alembic管理表结构版本，应用启动不再自行创建全部表。
- 每条用户数据保留user_id，查询和写入统一检查归属。
- 任务与执行时段一对多，一个任务分多日执行仍只统计一次；完成执行时段与完成整个任务分别处理。
- 确认候选与采纳推荐使用数据库事务，唯一键`(user_id, proposal_id)`防重复采纳，幂等键覆盖重复点击与网络重试。
- 编辑使用version或ETag乐观锁，过期版本返回409及合并提示，避免多标签页静默覆盖。
- 证据撤回后重新生成当前报告，历史报告保留生成时间及引用证据版本，趋势只比较有意义的历史记录。

验收：Docker+PostgreSQL真实运行，重启后数据保留；跨用户访问拒绝；重复请求不重复写入；并发编辑可检测冲突；备份恢复有测试。

## 重复日程

重复规则保存“星期集合、生效起止日期、学期首周、周次范围、单双周和节次映射”，不使用无限重复的简单字符串。

- 用Asia/Shanghai时区将规则展开为查询窗口内的发生实例；具体执行时段关联同一个task_id。
- “仅本次”修改写入日期例外；“整个系列”修改规则，并在保存前显示受影响日期与数量。删除同理。
- 对所有受影响实例重新检查冲突，使用左闭右开区间`a.start < b.end && b.start < a.end`；首尾相接不冲突。
- 用户选择修改、取消或同时保留后才提交；缺失学期日期、节次表或教学周时保持待补充，不生成猜测的正式安排。
- ICS采用成熟解析库处理时区、RRULE、EXDATE和RECURRENCE-ID，替换当前简化导入器。

验收：普通周、单双周、学期首周换算、单次例外、系列编辑、跨日实例、边界时间、重复计数和ICS时区均有测试。

## 验证顺序

先锁定四类候选Schema和带来源的真实模型用例；再完成领域模型及事务接口；随后逐页React迁移；最后运行浏览器端到端、PostgreSQL持久化与并发、视觉及性能测试。所有阶段使用同一套固定输入，替换Qwen时复跑，不以模型回答“看起来合理”作为验收依据。
