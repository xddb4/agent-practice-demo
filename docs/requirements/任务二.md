## 任务二 产品定义

### 1 产品定位陈述

希望提升自己的科研素养的学生，有管理的学习任务与反思不足的需求。StudyPilot面向科研初入门者，旨在帮助其发展科研学习素养，辅助时间规划的产品。通过关联行为与能力，辅助用户管理时间与任务，并生成成长式素养评估。不同于仅提醒的日历待办产品和缺乏长期有效的建议的普通AI助手，StudyPilot可根据用户的任务完成情况与偏向，动态跟踪个人素养变化，提出个性化发展建议。

### 3 用户问题

1. 疲于规划繁忙的学习任务
2. 对长期目标缺乏清晰着手点
3. 希望针对性提升自身科研学习素养

### 4 解决方案

1. 按艾森豪威尔矩阵四象限法则，和是否固定时间点任务两种分类方式划分任务，辅助用户确定任务是否冲突，完成优先级顺序，与番茄ToDo,YoYo日常等日程管理辅助软件形成对比。
2. 根据用户科研学习素养，对长期灵活性任务进行针对性的任务分解与建议，供用户参考采纳，与只记录任务的自律类软件形成区分，给出更精确建议。
3. 智能体识别任务类型，偏向优先完成、完成度高的任务，辅以用户自行输入的成果反馈，进行个人素养评估的动态调整，与一般智能体助手形成区分，长期跟踪用户个人素养。

### 5.1 计划页面与排序要求

页面布局：采用“左侧每日计划 + 右侧四象限”。左侧按固定与非固定任务分区展示，顶部显示日期及时间分配情况，所有任务保留四象限标签。

任务分类：固定任务（fixed）按开始时间排列，与日历数据同步；非固定任务（flexible）展示预计时长、DDL、能力关联及建议时段，支持拖动调整。

四象限管理：右侧四象限分别展示任务数量、最早 DDL 和摘要，通过颜色区分优先级，支持任务与每日计划双向拖动。

排序规则：非固定任务默认按 DDL 升序排列；DDL 相同时按象限优先级、预计耗时降序排列，支持手动排序与恢复默认。

智能排程：优先校验并锁定固定日程，再安排非固定任务及缓冲时间；时间不足时提示冲突原因和调整建议。
### 5.2 领域职责与实现原则

采用“规则引擎 + 结构化模型 + 大模型解释”的混合架构。

Task Planner：任务拆解、四象限分类与时间排程。

Skill Mapper：建立任务与能力指标的关联。

Evidence Extractor：提取能力证据并保留来源。

Assessment Engine：依据规则更新能力评分及置信度。

Recommendation Engine：生成建议，经用户确认后纳入计划。

Feedback Loop：收集执行反馈，持续优化规划。

实现原则：排程、优先级及评分由确定性规则处理，大模型负责信息解析、解释和建议生成。统一管理任务、日程、能力、证据与反馈数据，记录关键调整及其原因，确保结果可解释、可追溯。

### 6 能力维度与指标体系

能力模型采用“维度—指标—证据—反馈”四层结构，第一版统一使用以下六个维度。能力分数是当前估计，不是固定标签；建议以 0 至 100 分呈现，同时保存并展示 `score`、`confidence`、`evidence_count`、`last_updated` 和 `trend`，每个分数都能追溯到用户可查看的证据及变化原因。

| 能力维度 | 建议指标                             | 数据来源                   | 
| -------- | ------------------------------------ | -------------------------- | 
| 问题发现与研究设计 | 提出可验证问题；定义变量、基线和评价标准 | 研究计划、实验设计、选题说明 | 
| 计算与系统思维 | 建立分层模型；解释硬件、软件和性能关系 | 系统分析、架构图、代码/电路实验 | 
| 实验验证与数据素养 | 记录实验条件；开展对照；解释异常数据 | 实验日志、数据表、复现实验、结果图 | 
| 批判性与独立思考 | 质疑结论、工具输出和前提；比较替代方案 | 失败记录、反例、方案比较、AI 使用说明 | 
| 信息素养与学术规范 | 检索、筛选、引用和复述文献；遵守数据与学术诚信 | 文献卡片、引用记录、数据来源 |
| 表达、协作与反思 | 清楚表达方法与限制；吸收反馈并迭代 | 周报、汇报、论文草稿、复盘自述 | 



### 7 四象限处理规则

| 象限         | 判断原则                           | 系统建议                                 | 典型示例                    |
| ------------ | ---------------------------------- | ---------------------------------------- | --------------------------- |
| 重要且紧急   | 影响核心目标且临近截止或已造成阻塞 | 立即安排 明确完成标准 必要时拆分并预警   | 明日考试复习 当天项目故障   |
| 重要不紧急   | 对长期目标影响大但仍有时间窗口     | 放入阶段计划 拆成连续小任务 保护固定投入时间 | 科研训练 论文准备      |
| 不重要但紧急 | 时间敏感但对核心目标贡献低         | 批量处理 限制占用深度工作时间            | 一般性通知 临时资料整理     |
| 不重要不紧急 | 影响低且无明确时限                 | 延后 合并或建议删除                      | 无目的刷信息 重复低价值整理 |

四象限属性与每日任务类型独立。例如“周五 16:00 的导师汇报”可以是“重要且紧急 + 固定时间点任务”，“本周完成实验报告”可以是“重要不紧急 + 非固定时间点任务”。保护长期任务的投入时间，不意味着把所有此类任务改为不可移动的固定日程。

### 8 同类产品与差异化方案

- 与日历产品相比：StudyPilot不只安排时间，还解释任务为何被安排以及它关联哪项能力。
- 与待办产品相比：StudyPilot强调目标拆解、时长估算、精力约束和动态重排，而不是静态清单。
- 与通用 AI 助手相比：StudyPilot维护长期结构化状态，包括目标、任务、计划、实际执行和能力证据。
- 与学习分析产品相比：StudyPilot面向用户主动规划，支持跨课程、跨项目和个人生活的统一管理。

### 9 建议里程碑与交付计划

当前先交付需求拆解、领域模型和系统架构设计。后续实现按以下四阶段推进，每阶段的开发与验收再结合团队资源确认，不将全部功能提前纳入首个可用版本。

| 实现阶段 | 主要范围 | 验收标准 |
| -------- | -------- | -------- |
| 阶段一：可用的个人计划 | 创建目标、任务和固定日程；四象限自动判断与覆盖；固定与非固定任务分类；先固定后弹性排程；当天计划与固定日历；完成、延期、跳过和复盘 | 用户能在 3 分钟内输入一个目标，得到包含固定任务时间轴与非固定任务建议时段的当天计划；不能生成固定时间冲突 |
| 阶段二：能力可视化 | 建立六维指标字典，选择或推荐任务能力关联，基于完成质量与复盘生成报告，展示证据、置信度和变化原因 | 任何能力分数都可追溯到至少一条用户可查看的证据 |
| 阶段三：反馈与成果分析 | 上传或粘贴作品、论文结果和自述；抽取结构化信息；用户确认、修改或拒绝证据；确认后回流报告与建议 | 用户可以纠正系统错误，错误不会直接污染后续能力评估 |
| 阶段四：个性化机会推荐 | 输入比赛、课程、项目或论文机会；对照能力、时间预算与历史成果解释匹配；认同后生成准备任务并加入“重要不紧急”；按完成情况重评可行性 | 推荐包含理由、预计投入、影响能力、接受后的计划变化和用户确认步骤 |
