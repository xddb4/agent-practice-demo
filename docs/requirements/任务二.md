### 3 问题与客户价值

| 核心问题       | 用户影响                                      | 研时提供的价值                            | 建议验证指标                   |
| -------------- | --------------------------------------------- | ------------------------------------------------ | ------------------------------ |
| 目标难以落地   | 目标停留在愿望层面 每天不知道先做什么         | 把目标拆成阶段里程碑 周任务和每日行动            | 首次规划完成率大于等于 70%     |
| 任务优先级混乱 | 被紧急事项牵引 重要但不紧急的成长任务长期推迟 | 依据截止期 影响范围 依赖和用户偏好生成四象限分类 | 用户认可分类比例大于等于 75%   |
| 计划与现实脱节 | 低估时长 忽略精力与突发事项 导致频繁放弃      | 结合可用时间 精力曲线与缓冲自动排程              | 计划按时完成率逐周提升         |
| 成长不可见     | 完成大量任务却难以说明能力提升在哪里          | 把任务证据映射到能力指标并生成雷达图与趋势       | 周复盘查看率大于等于 50%       |
| 复盘成本高     | 记录零散 难以从结果中调整下一周期             | 自动汇总偏差原因并提出可解释调整建议             | 连续使用四周留存率大于等于 30% |

### 4 解决方案与核心工作流

1. 目标与约束采集：获取目标、截止日期、固定日程、可用时间与精力偏好；能力基线后续分步补充，不阻塞首次规划。
2. 任务结构化与能力关联：将目标拆为阶段里程碑、任务和最小行动，估算时长、依赖与风险，选择或推荐关联的能力指标并说明依据。
3. 四象限分类：根据截止时间、目标关联、影响范围和用户输入自动判断，显示判断理由，允许用户覆盖；修改记录为偏好信号，不直接改变能力分数。
4. 每日任务分类与排程：四象限决定优先级，固定时间点任务和非固定时间点任务决定执行时间形态，两者不能互相替代。先校验固定冲突并锁定固定任务，再在剩余时间内为非固定任务分配建议时段，保留休息与缓冲。
5. 执行与反馈：支持完成、延期、跳过和复盘，记录完成度、实际耗时与阻塞点，用于优化计划和偏好。
6. 成果提交与证据确认：上传或粘贴阶段作品、论文结果和自我叙述，抽取问题、方法、实验、结果、限制与反思，保留原文来源及引用位置；用户可确认、修改或拒绝提取结果，确认后才用于后续能力评估。
7. 能力报告更新：结合连续行为记录、完成质量、复盘和已确认的提取证据，用可解释规则更新六维能力的分数、置信度和趋势，展示变化原因与证据来源；完成任务不直接等于能力提升。
8. 周期复盘与机会推荐：根据新目标、能力短板、时间预算和历史成果提出比赛、课程、项目或论文机会，说明理由、影响能力、预计投入及接受后对计划的影响。必须经用户认同后，才生成准备阶段任务并加入“重要不紧急”，随后根据完成情况重新评估可行性。

### 5.1 计划页面与排序要求

- 页面采用“左侧每日计划 + 右侧四象限”。左侧上部为固定时间点任务的课表或时间轴，下部为非固定时间点任务条目；顶部显示日期、可用时间、已安排时长和未安排时长。每日任务必须保留四象限标签。
- 固定时间点任务具有明确开始和结束时间，通常不可自由移动，按开始时间排序，展示任务名称、时间、地点、重复规则和象限备注。课程、会议、实验室例会和睡眠等固定或不可用时段进入独立日历模型，并对应 `fixed` 类型；固定日程页面与计划页面使用同一份数据，避免重复维护。
- 非固定时间点任务对应 `flexible` 类型，展示完成框、名称、预计时长、DDL、能力关联、建议时间段和象限标签，允许拖动或修改建议时段。
- 右侧四个独立小方块分别展示四个象限的名称、任务数量、最早 DDL 和任务摘要，使用不同颜色层级，对“重要且紧急”加强视觉强调。支持从小方块拖入每日计划，以及从每日计划拖回小方块调整优先级；四象限区域不能替代每日执行列表。
- 非固定任务默认按 DDL 从近到远排序；DDL 相同时依次按“重要且紧急、重要不紧急、不重要但紧急、不重要不紧急”排列，同一象限内再按预计耗时从长到短排列。用户可手动调整当天执行顺序，并可恢复“按 DDL 排序”。固定任务不参与此排序，右侧各象限内也默认按 DDL 从近到远排列。
- 排程先校验固定时间冲突，再锁定固定任务，最后分配非固定任务建议时间块，并预留缓冲。无法全部安排时，说明剩余时长、冲突原因及可延期选项；象限区域的排序仍影响每日非固定任务默认顺序，用户可手动调整。

### 5.2 领域职责与实现原则

采用“规则引擎 + 结构化模型 + 大模型解释”的混合架构。Task Planner 负责拆解、排程和四象限，不直接修改能力分数；Skill Mapper 维护任务与能力指标映射；Evidence Extractor 提取证据并保留原文来源；Assessment Engine 根据可解释规则更新分数与置信度；Recommendation Engine 生成候选并等待用户认同后入计划；Feedback Loop 回收执行记录、修正和建议接受度。

排程、四象限和分数更新由确定性代码完成，大模型用于自然语言材料解析、解释和候选方案生成。领域模型应覆盖用户与时区、目标、任务、固定日程、计划时间块、能力指标、评估、证据、反馈、推荐及审计日志，记录计划调整、用户覆盖和能力变化的原因与来源。

### 6 能力维度与指标体系

能力模型采用“维度—指标—证据—反馈”四层结构，第一版统一使用以下六个维度。能力分数是当前估计，不是固定标签；建议以 0 至 100 分呈现，同时保存并展示 `score`、`confidence`、`evidence_count`、`last_updated` 和 `trend`，每个分数都能追溯到用户可查看的证据及变化原因。

| 能力维度 | 建议指标                             | 数据来源                   | 示例解释                           |
| -------- | ------------------------------------ | -------------------------- | ---------------------------------- |
| 问题发现与研究设计 | 提出可验证问题；定义变量、基线和评价标准 | 研究计划、实验设计、选题说明 | 反映问题定义与研究方案设计能力 |
| 计算与系统思维 | 建立分层模型；解释硬件、软件和性能关系 | 系统分析、架构图、代码/电路实验 | 反映系统建模与关联分析能力 |
| 实验验证与数据素养 | 记录实验条件；开展对照；解释异常数据 | 实验日志、数据表、复现实验、结果图 | 反映实验验证与数据解释能力 |
| 批判性与独立思考 | 质疑结论、工具输出和前提；比较替代方案 | 失败记录、反例、方案比较、AI 使用说明 | 反映证据审视与独立判断能力 |
| 信息素养与学术规范 | 检索、筛选、引用和复述文献；遵守数据与学术诚信 | 文献卡片、引用记录、数据来源 | 反映信息处理与学术规范意识 |
| 表达、协作与反思 | 清楚表达方法与限制；吸收反馈并迭代 | 周报、汇报、论文草稿、复盘自述 | 反映表达、协作与反思改进能力 |

第一版采用可解释的证据权重建议：阶段作品或论文结果 0.35，连续行为记录 0.25，任务完成质量与复盘 0.20，用户自评和自我叙述 0.10，用户对系统建议的接受或拒绝 0.10。一次证据只能小幅改变分数，多次同方向证据和不同来源相互印证后才提高置信度。建议接受或拒绝也需结合上下文解释，不能直接等同于能力高低；用户修改优先级仅用于偏好优化，不直接改变能力分数。

完成任务不直接等于能力提升，应记录问题是否清晰、是否设置基线、是否解释异常、是否比较方案、是否反思 AI 输出、是否根据反馈迭代等过程证据。系统提取的证据须保留原文来源及引用位置，并允许用户确认、修改或拒绝；仅将确认后的提取证据回流能力评估和计划建议，避免错误污染后续评估。

### 7 四象限处理规则

| 象限         | 判断原则                           | 系统建议                                 | 典型示例                    |
| ------------ | ---------------------------------- | ---------------------------------------- | --------------------------- |
| 重要且紧急   | 影响核心目标且临近截止或已造成阻塞 | 立即安排 明确完成标准 必要时拆分并预警   | 明日考试复习 当天项目故障   |
| 重要不紧急   | 对长期目标影响大但仍有时间窗口     | 放入阶段计划 拆成连续小任务 保护固定投入时间 | 科研训练 论文准备      |
| 不重要但紧急 | 时间敏感但对核心目标贡献低         | 批量处理 限制占用深度工作时间            | 一般性通知 临时资料整理     |
| 不重要不紧急 | 影响低且无明确时限                 | 延后 合并或建议删除                      | 无目的刷信息 重复低价值整理 |

四象限属性与每日任务类型独立。例如“周五 16:00 的导师汇报”可以是“重要且紧急 + 固定时间点任务”，“本周完成实验报告”可以是“重要不紧急 + 非固定时间点任务”。保护长期任务的投入时间，不意味着把所有此类任务改为不可移动的固定日程。

### 8 同类产品与差异化方案

- 与日历产品相比：研时不只安排时间，还解释任务为何被安排以及它关联哪项能力。
- 与待办产品相比：研时强调目标拆解、时长估算、精力约束和动态重排，而不是静态清单。
- 与通用 AI 助手相比：研时维护长期结构化状态，包括目标、任务、计划、实际执行和能力证据。
- 与学习分析产品相比：研时面向用户主动规划，支持跨课程、跨项目和个人生活的统一管理。
