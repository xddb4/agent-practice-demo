# 个人科研成长规划智能体：问题定义

## 0. 5W1H

### Who：谁使用，谁受益

第一版面向需要同时管理课程、科研、作业、竞赛和个人成长的本科生个人用户，尤其适合计算机系统、处理器芯片及相关工科方向学生。

直接使用者是学生本人。学生可以输入目标和任务、查看每日计划、修改智能体判断、提交阶段成果，并查看能力发展报告。

系统未来可以扩展导师、教师和管理员角色，但第一版不开放多人协作和导师管理后台。

### What：要解决什么问题

系统要解决以下问题：

1. 用户有许多任务，但不知道哪些任务更重要、更紧急。
2. 固定课程、会议等时间点任务与作业、阅读、实验等非固定任务混在一起，计划难以执行。
3. 普通待办工具只能记录“做什么”，不能说明任务正在训练哪项能力。
4. 能力评估容易停留在主观印象，缺少行为、作品和反馈证据。
5. 比赛、课程或项目推荐没有结合用户的能力状态和时间预算。
6. 用户完成任务后，执行结果没有回流到下一轮计划和能力评估。

系统需要把目标、任务、时间、行为、阶段成果和能力评估连接成一个闭环。

### When：什么时候使用

用户可以在以下场景使用系统：

- 每天开始时查看当天的固定安排和待完成任务；
- 创建新目标、任务或固定日程时；
- 任务完成、延期或遇到阻塞时；
- 完成实验、课程项目、比赛作品或论文阶段工作后；
- 进行日复盘、周复盘或阶段总结时；
- 需要规划未来比赛、课程或科研机会时。

系统应支持按日、周和阶段查看计划，但第一版的核心执行单位是“每日计划”。

### Where：在哪里使用，数据来自哪里

第一版以个人 Web 应用为主要载体，用户通过浏览器访问。

数据来源包括：

- 用户手动输入的目标、任务和固定日程；
- 真实日历的 ICS 文件导入；
- 系统生成的任务完成记录和计划调整记录；
- 用户粘贴或上传的作品、论文结果和自我叙述；
- 用户确认后的能力证据；
- 用户输入的比赛、课程或项目链接。

第一版支持 ICS 导入和导出，不要求立即接入具体第三方日历的 OAuth 服务。比赛信息优先采用用户提供的官方链接或手动录入，系统应显示官方来源，不默认批量抓取网站内容。

### Why：为什么需要这个系统

人工智能降低了获取代码、答案和技术方案的门槛，但“会使用工具”不等于“理解原理、能够验证和独立创新”。参考论文指出，科研素养与问题提出、研究设计、实验验证、数据分析、结果解释、反思、信息素养、批判性思维和学术规范等过程能力有关；学习行为也可以作为能力发展的外显证据。

因此，系统的创新点不是简单增加一个待办列表，而是：

- 以时间作为成长主线；
- 把任务和六个能力维度关联；
- 用行为、作品和反馈形成可追溯证据；
- 让能力评估反过来影响任务建议和长期规划；
- 保留用户对系统判断的直接修正权。

### How：系统如何工作

```text
用户输入目标、任务、固定日程或阶段成果
        ↓
系统提取任务、DDL、时长、固定时间和能力关联
        ↓
系统默认判断四项优先级，用户可以直接修改
        ↓
每日计划先安排固定时间点任务
        ↓
剩余时间安排非固定时间点任务，并按 DDL 排序
        ↓
用户执行、完成、延期、跳过或复盘
        ↓
系统从行为、作品和自述提取能力证据
        ↓
更新能力水平、趋势和置信度
        ↓
根据目标、能力和时间预算提出下一轮计划或机会推荐
        ↓
用户确认后才将推荐加入正式目标和计划
```

### 1 产品定位陈述

对于希望提升自己的科研素养的学生，他们需要管理繁忙的学习任务，阶段性反思自己的能力不足。StudyPilot是一个面向科研初入门者发展科研素养与辅助时间规划的智能体。                                |
它能够关联行为与能力，给出用户的素养报告，辅助用户管理时间与任务。
不同于只负责记录提醒的日历待办产品和缺乏长期有效的发展建议的AI助手，我们的产品可以根据用户的任务完全情况与偏向，动态跟踪个人素养，并通过个人素养给相对自由的任务提出建议

## 2. 目标与非目标

### 2.1 产品目标

- 把用户的长期目标转化为当天可执行的计划。
- 将任务分为固定时间点任务和非固定时间点任务。
- 使用四项判断任务优先级，并允许用户直接修改。
- 让固定任务以课表/时间轴形式呈现。
- 让非固定任务以条目形式呈现，并默认按 DDL 从近到远排序。
- 建立六个科研能力维度及其可观察指标。
- 根据行为、成果、自述和外部反馈形成能力证据链。
- 用定量和定性相结合的方式展示能力水平。
- 通过 ICS 与真实日历进行导入和导出。
- 根据能力、方向和时间预算提供比赛、课程、项目等机会建议。
- 让所有推荐经过用户确认后再进入正式计划。

### 2.2 第一版非目标

- 不实现多人协作和导师管理后台。
- 不自动报名比赛、提交论文或操作外部系统。
- 不在没有授权的情况下批量抓取比赛网站。
- 不自动将非固定任务拆成多个子任务。
- 不把能力分数作为单一的高风险评价依据。

## 3. 用户角色与权限

### 3.1 第一版角色

第一版只实现个人学生用户。用户拥有自己的目标、任务、日历、证据和报告。

### 3.2 未来角色

后续可以增加导师、教师和管理员角色，但需要另行定义数据可见范围、评价权限和审批流程。

### 3.3 用户控制权

用户可以：

- 直接修改系统对任务的四项判断；
- 修改或删除系统生成的计划时间；
- 修改系统从材料中提取的能力证据；
- 拒绝某条证据进入能力评估；
- 接受或拒绝比赛、课程和项目推荐；
- 导出自己的任务、日程和报告数据。

系统需要记录重要修改，但不要求用户为每次修改填写原因。

## 4. 任务与计划需求

### 4.1 任务的双层分类

每项任务同时具有两种属性：

#### 四项优先级

- 重要且紧急；
- 重要不紧急；
- 不重要但紧急；
- 不重要不紧急。

系统先给出默认判断，用户可以直接调整。重要且紧急任务需要更强的颜色、排序和提醒强调。

#### 每日任务类型

- **固定时间点任务**：有明确开始时间和结束时间，例如课程、会议和实验室例会。
- **非固定时间点任务**：有完成期限或 DDL，但没有固定开始时间，例如作业、论文阅读、实验分析和比赛准备。

两种属性可以叠加。例如：

```text
导师汇报 = 重要且紧急 + 固定时间点任务
实验报告 = 重要不紧急 + 非固定时间点任务
```

### 4.2 计划页面

计划页面使用“左侧每日计划 + 右侧四项小方块”的布局。

左侧上部是固定时间点任务，使用类似课表或时间轴的形式呈现，显示：

- 日期；
- 开始时间和结束时间；
- 任务名称；
- 地点或会议方式；
- 重复规则；
- 所属四项。

左侧下部是非固定时间点任务，使用纵向条目呈现，显示：

- 完成状态；
- 任务名称；
- DDL；
- 预计时长；
- 建议执行时间；
- 能力关联；
- 所属四项；
- 完成标准。

右侧显示四个独立小方块，每个小方块包含象限名称、任务数量、最近 DDL 和任务摘要。四个小方块都可用于查看和调整任务，其中“重要且紧急”需要更明显的视觉强调。

每日任务条目必须保留四项标签，不能因为按每日计划展示而隐藏优先级信息。

### 4.3 排序规则

固定时间点任务按开始时间从早到晚排序，不参与非固定任务的 DDL 排序。

非固定时间点任务默认按以下规则排序：

1. DDL 从近到远；
2. 相同 DDL 时按四项优先级排序：重要且紧急、重要不紧急、不重要但紧急、不重要不紧急；
3. 同一象限内按预计耗时从长到短。

用户可以手动调整当天执行顺序，系统需要提供“恢复按 DDL 排序”操作。右侧四个小方块中的任务也按 DDL 从近到远显示。

### 4.4 计划生成

生成每日计划时，系统应：

1. 读取真实日历和系统内固定日程；
2. 检查固定时间点任务冲突；
3. 锁定固定时间点任务；
4. 计算当天剩余可用时间；
5. 按 DDL 和四项优先级安排非固定时间点任务；
6. 预留合理缓冲时间；
7. 输出当天计划和未安排任务说明。

非固定任务第一版不自动切分。系统只建议执行时间段，用户可以自行调整或在后续版本手动拆分。

## 5. 日历需求

### 5.1 ICS 导入

用户可以导入 ICS 文件。系统应识别事件名称、开始时间、结束时间、重复规则、地点和描述，并将事件作为固定时间点任务或不可用时间段处理。

### 5.2 ICS 导出

用户可以将系统中的固定日程和已确认的计划时间块导出为 ICS 文件，以便导入其他日历应用。

### 5.3 冲突处理

当导入日历与系统已有固定任务冲突时，系统应显示冲突明细，由用户选择保留、覆盖或取消导入。系统不能静默覆盖用户原有日程。

## 6. 六个能力维度

系统第一版使用六个能力维度：

1. **问题发现与研究设计**：提出问题、定义目标、设置变量、设计方案和评价标准。
2. **计算与系统思维**：建立分层模型，理解硬件、软件、数据和性能之间的关系。
3. **实验验证与数据素养**：记录条件，设置对照，处理数据，解释异常并验证结论。
4. **批判性与独立思考**：质疑前提、工具输出和结论，比较替代方案，避免机械依赖 AI。
5. **信息素养与学术规范**：检索和筛选文献，准确引用，管理数据，遵守研究伦理和学术诚信。
6. **表达、协作与反思**：清晰表达方法、结果和限制，吸收反馈并推动方案迭代。

每个维度还需要维护指标定义、证据类型和下一步建议，不能只保留一个分数。

## 7. 能力评估需求

### 7.1 定量与定性结合

能力评估不强制全部使用 0-100 分，采用三种表达方式：

- **可量化指标**：任务完成率、按时完成率、实验记录完整度、复盘频率、方案迭代次数等；
- **半定量能力**：研究设计、系统思维、实验验证等，可以使用“初步、发展中、熟练、较强”等等级，并显示趋势和置信度；
- **定性能力**：批判性思维、独立思考、学术表达和反思质量，显示当前判断、主要证据、优势、待提升点和下一步建议。

报告统一展示：

```text
能力水平 + 发展趋势 + 置信度 + 证据说明 + 下一步建议
```

### 7.2 评估稳定性

一次任务完成、一次自评或一段自述不能造成能力水平的大幅变化。系统应区分：

- 能力水平：当前估计；
- 置信度：证据是否充分、来源是否一致；
- 趋势：近期上升、稳定或下降。

每次变化都应显示变化原因和关联证据。

## 8. 证据与反馈需求

### 8.1 证据来源

系统可以使用：

- 行为记录：开始、完成、延期、复盘、失败记录、方案修改和资料比较；
- 阶段作品：实验报告、课程项目、比赛作品、论文草稿和开源代码；
- 用户自述：对困难、方法、结果和限制的自然语言说明；
- 外部反馈：教师、导师、队友、评审或审稿意见。

### 8.2 证据确认

系统从用户材料中提取候选证据后，必须让用户确认。用户可以接受、修改、拒绝或标记“需要后续观察”。只有确认后的证据才能正式影响能力报告。

### 8.3 反馈回流

用户提交完成度、实际用时、阻塞点、失败原因、作品或论文结果后，系统形成：

```text
反馈
→ 候选证据
→ 用户确认
→ 能力评估更新
→ 下一轮计划建议
```

## 9. 机会推荐需求

用户可以输入比赛、课程、项目或论文机会的名称和官方链接。系统基于用户方向、能力状态、能力短板、时间预算、已有成果、截止日期和预计工作量生成候选推荐。

每条推荐必须说明：

- 推荐名称和官方来源；
- 推荐理由；
- 匹配的能力；
- 需要补足的能力；
- 预计准备周期和时间投入；
- 对现有计划的影响；
- 建议生成的任务。

推荐流程为：

```text
系统推荐 → 用户查看理由 → 用户认同或拒绝
→ 认同后加入目标 → 生成准备任务 → 进入重要不紧急
```

第一版不自动报名、不自动提交材料，也不在缺乏授权时批量抓取比赛方网站。优先使用用户提供的官方链接、手动录入和得到授权的公开接口。

## 10. 智能体职责边界

系统可以按以下职责拆分智能体或领域服务：

- 输入理解：识别用户是在创建任务、设定目标、查询计划还是提交反馈；
- 任务分析：提取任务名称、DDL、时长、固定时间和能力关联；
- 四项判断：给出重要性和紧急性默认判断；
- 时间规划：先安排固定时间点任务，再安排非固定时间点任务；
- 能力映射：判断任务关联的能力维度和指标；
- 证据分析：从行为、作品和自述中提取候选证据；
- 能力评估：更新能力水平、趋势和置信度；
- 机会推荐：根据目标和能力状态生成候选机会；
- 反馈回流：接收用户修改并影响下一轮计划。

任务排序、固定时间冲突检测和能力变化规则应优先由确定性代码完成。大模型用于自然语言理解、证据提取、解释和候选建议生成。

## 11. 非功能需求

### 11.1 可解释性

系统生成的四项判断、任务排序、能力变化和机会推荐都应提供简要理由。

### 11.2 可控性

用户可以直接修改系统判断。系统不能在用户未确认时把推荐加入正式目标，也不能在未确认时用候选证据更新正式能力报告。

### 11.3 可追溯性

能力评估变化、任务分类修改、日历冲突处理和推荐接受结果都需要保留记录。

### 11.4 隐私与数据控制

用户上传的作品、自述、论文结果和日历属于个人数据。系统需要支持查看、删除和导出，第三方模型调用前应明确数据范围和保存策略。

### 11.5 可用性

用户应能在较短时间内创建目标并得到当天计划。固定任务和非固定任务在视觉上必须明显区分，重要且紧急任务必须容易发现。

## 12. 第一版验收标准

第一版达到以下条件即可视为核心需求完成：

1. 用户可以创建目标、固定时间点任务和非固定时间点任务。
2. 系统可以为任务生成四项默认判断，用户可以直接修改。
3. 计划页面左侧上下分区显示每日任务，右侧以四个小方块显示四项。
4. 固定任务以课表/时间轴形式展示，非固定任务以条目展示。
5. 非固定任务默认按 DDL 从近到远排序，并保留四项标签。
6. 系统能检测固定时间冲突，并在排程时优先锁定固定任务。
7. 用户可以导入和导出 ICS 日历。
8. 系统展示六个能力维度，并支持定量与定性结合的报告。
9. 用户可以提交文本和文件形式的阶段成果或自述。
10. 系统提取的能力证据需要用户确认后才进入正式报告。
11. 比赛或项目推荐展示来源、理由和时间投入，用户确认后才加入计划。
12. 用户可以查看任务、证据和能力变化之间的关系。
