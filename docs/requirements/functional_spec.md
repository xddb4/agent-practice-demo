# 功能需求规范

## 1. 任务与目标

系统应支持创建、编辑、完成、延期、跳过和删除目标与任务。任务至少包含名称、DDL、预计时长、任务类型、四项优先级、能力关联和完成标准。

任务类型分为固定时间点任务和非固定时间点任务。四项优先级与任务类型独立存在，可以组合使用。

系统先生成四项默认判断，用户可以直接修改，不强制填写原因。

## 2. 每日计划

计划页面采用左侧每日计划、右侧四项小方块的布局。

左侧上部以课表或时间轴展示固定时间点任务，包含开始时间、结束时间、地点、重复规则和四项标签。左侧下部以条目展示非固定任务，包含完成状态、DDL、预计时长、建议时间、能力关联、四项标签和完成标准。

固定任务按开始时间排序；非固定任务默认按 DDL 从近到远排序，相同 DDL 时按四项优先级排序，再按预计时长排序。用户可手动调整，并可恢复默认排序。

## 3. 四项小方块

右侧显示四个独立小方块：重要且紧急、重要不紧急、不重要但紧急、不重要不紧急。每个方块显示任务数量、最近 DDL 和任务摘要。“重要且紧急”应重点强调。任务可在小方块和每日计划之间调整。

## 4. 时间排程

系统排程顺序为：读取日历、检测固定任务冲突、锁定固定任务、计算可用时间、为非固定任务推荐时间段、预留缓冲并报告未安排任务。第一版不自动切分非固定任务。

## 5. 真实日历

系统应支持 ICS 导入和导出。导入时读取事件名称、时间、地点、描述和重复规则；发现冲突时展示明细，由用户选择保留、覆盖或取消，不能静默覆盖已有日程。

## 6. 能力报告

系统使用六个能力维度：问题发现与研究设计、计算与系统思维、实验验证与数据素养、批判性与独立思考、信息素养与学术规范、表达协作与反思。

报告应显示能力水平、趋势、置信度、证据数量、主要证据和下一步建议。能力可以用数值、等级或定性描述表达，不强制所有维度使用 0-100 分。

## 7. 证据与反馈

系统支持记录行为、上传或粘贴阶段作品、论文结果和用户自述，并可接收外部反馈。系统先生成候选证据，用户可以接受、修改、拒绝或标记为待观察；未经确认的证据不能更新正式报告。

## 8. 个性化推荐

用户可以输入比赛、课程、项目或论文机会及官方链接。系统根据方向、能力、短板、时间预算、DDL 和预计工作量生成推荐，展示来源、理由、能力匹配和新增任务。用户确认后才能加入目标和“重要不紧急”计划。

## 9. 功能验收

- 可创建两类每日任务并设置四项；
- 计划页按上下区域呈现每日任务，右侧呈现四个小方块；
- 非固定任务按 DDL 排序并保留四项标签；
- 固定任务冲突可被检测和处理；
- ICS 可导入、导出；
- 六个能力维度可查看证据和趋势；
- 用户可确认或拒绝候选证据；
- 推荐经过确认后才进入计划。
