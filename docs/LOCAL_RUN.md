## 启动

推荐安装 Docker Desktop 后在仓库根目录执行：

```powershell
Copy-Item .env.example .env
# 在 .env 中填写 MODEL_API_KEY；不要提交此文件
docker compose up --build -d
```

打开 http://127.0.0.1:8000 ，API 文档为 http://127.0.0.1:8000/docs 。Docker 模式使用 PostgreSQL 16，附件和数据库分别持久化到命名卷。停止用 `docker compose down`，不要加 `-v`，后者会删除持久数据。

本机已准备 `.runtime` Python 依赖和 `frontend/dist` 静态构建，可以执行：

```powershell
.\start.ps1
```

此方式默认使用 SQLite，便于没有 Docker 时验证本地交互；它不能证明 PostgreSQL 集成已经通过。可通过 `DATABASE_URL` 指向真实 PostgreSQL。Python 默认路径为本机 Anaconda，也可使用 `start.ps1 -Python 其他Python路径`。

重新准备依赖与构建：

```powershell
python -m pip install --target .runtime -r backend/requirements.txt
cd frontend
npm install
npm run build
cd ..
```

## 配置 Agent

复制 `.env.example` 为 `.env`，填写 `MODEL_API_KEY`。默认使用 Qwen 的 OpenAI 兼容接口；地域不同需相应修改 `MODEL_BASE_URL`。`MODEL_NAME` 为文本模型，`VISION_MODEL` 为视觉模型。适配层通过兼容接口接入，可后续换供应商及模型；目前配置为部署级别，尚未提供每个用户自选密钥的设置界面。

配置 `TAVILY_API_KEY` 后，推荐流程可检索公开来源。未配置或搜索失败时，返回“未取得外部来源”，不声称日期已经核实。检索来源仅展示实际返回的链接。模型请求超时45秒、重试1次，推荐工具调用最多4轮。没有模型密钥时仅启用明确标识的离线规则候选，不模拟模型已联网。

1. 注册并登录。账户密码在服务端用随机盐和 PBKDF2 保存；邮箱尚未验证。
2. 日程录入 → 文字识别，输入通知 → React 核对弹窗 → 编辑或删除候选 → 在原型确认窗口核对日期与分类 → 确认入库。冲突时选择保留方式。
3. 图片录入 → 上传课表 → 识别 → 核对课程、教学周、学期首周及节次 → 确认导入。图片需要有效视觉模型。
4. 个人空间 → 能力报告 → 添加成长证据。支持粘贴材料或上传 PDF/UTF-8文本/图片附件。PDF提取正文，图片附件保存但证据正文仍需用户提供。Agent生成的内容先进入待确认；接受后才纳入报告，拒绝或待观察不纳入。附件下载校验归属。
5. 象限分化 → 个性化推荐，输入目标、DDL、每周时间及基础约束 → 生成候选 → 修改、删除候选 → 核对后加入计划。推荐流程内部使用画像/日程工具和搜索工具执行局部 ReAct。
6. ICS 保留原型中的导入导出入口。当前导入器仅覆盖基本 VEVENT 和每周规则，复杂时区与完整 RFC5545 规则仍需完善，导入时务必核对。

## 架构与依据

流程为 React 核对层 → FastAPI 登录校验 → LangGraph Router → 日程/证据/推荐 → 候选 → 用户确认 → 服务端保存。LangGraph 节点不会直接写入正式任务；推荐的工具只读。当前用户状态以 JSON 记录存储于 SQLAlchemy 数据表，支持 PostgreSQL 和 SQLite。

为保留原型的精确布局、嵌入素材和动效，当前 React 应用通过同源 iframe 承载原型，使用兼容适配层替换登录、存储、识别、推荐和报告逻辑，React 控制 Agent 核对窗口。**尚未完成全部原型页面到 React 组件的迁移**，不应将此版本描述为完整 React 重构。

参考两份论文的研究素养、过程证据、计算思维、验证、批判与反思框架；六个维度遵循功能需求。论文中的相关关系不用于生成用户个人因果结论，不用任务数量、速度或偏好推算能力等级。当前报告提供依据、证据不足、有限置信度和暂无可比历史；尚未实现经验证的能力等级评价器和历史趋势分析。

用户已确认的冲突决策：严格保留最终原型布局（灵活任务在计划页右侧、四象限独立页面）；原型本地账号替换为服务端账号；案例单独标注；ICS 保留。
