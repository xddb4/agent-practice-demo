## 默认条件与边界

- 默认能力配置为 `auto`，上下文中的已有任务和能力证据均为空。两个目标分别运行，避免相互影响。
- 不额外指定考试日期、组会日期、论文正文、用户水平或每周预算。不人为注入数字预算和日期，让模型在当前工作流的缺省路径下处理信息不足。
- 当前排期器需要目标截止日期和每周可投入时间；信息不足时允许提示无法完成排期。**推荐可读、候选合法与排期可行是不同检查项**，不能将约束不足说成排期已通过。
- 模型自主提出的练习周期或时长，应表述为建议或假设，不能说成用户提供的事实。
- 图片中的“第8周”不代表课程仅在第8周开设，也不代表第1—16周每周重复。输出课程候选时需要保留这个不确定性。
- 已过截止日期的通知仍用于检查历史解析，不自动调整日期。本脚本直接运行候选工作流，不调用保存、采纳或正式日程写入接口。
- 文本样例保留通知原意，仅规范了转义、换行和列表格式；原通知所引用的图片、Word、附件和在线表格未提供。不得按这些缺失材料推断细节。

## 复现方法

在仓库根目录执行。默认模式只生成待测清单，不读取账号数据库或密钥文件，不发起网络请求：

```powershell
python scripts/validate_user_samples.py
```

课表图不提交到公共仓库，保留用户原图于本机，通过参数传入；准备模式只检查文件是否存在：

```powershell
python scripts/validate_user_samples.py --case chinese_timetable --image "你的课表图片绝对路径.png"
```

报告默认保存在被 Git 忽略的 `.runtime/model-validation-2026.json`。包括五个样例的状态和人工检查清单。没有实际执行时，不能填写耗时、成功次数或准确率。

### 后续真实模型调用（本轮不执行）

安装项目后端依赖，使用单独测试进程设置 `MODEL_PROVIDER`、`MODEL_BASE_URL`、`MODEL_NAME`、`MODEL_API_KEY`。脚本不会自动读取网页账号配置、本地 `.env` 或其他账户密钥。密钥由本机环境提供，不写进命令记录、样例或报告。

文本样例运行示例：

```powershell
python scripts/validate_user_samples.py --live --case notice_training --case notice_awards --case goal_cet_spoken --case goal_paper_reading --output .runtime/model-validation-text-live.json
```

视觉样例还需实际支持图片输入的模型，设置 `MODEL_SUPPORTS_VISION=true` 和 `VISION_MODEL`。不要为通过配置检查而给纯文本模型打开视觉开关：

```powershell
python scripts/validate_user_samples.py --live --case chinese_timetable --image "你的课表图片绝对路径.png" --output .runtime/model-validation-vision-live.json
```

`--live` 会产生模型调用用量；推荐流程可能按现有工作流调用检索、校验修复与任务质量审查。模型和检索参数以进程环境为准，运行后保留报告中的调用指标、搜索状态和执行日期。为复现实验，还需记录当时的代码提交和服务商配置；不同文本、视觉模型要分别注明，不能统称为一个模型的成绩。

报告状态：

- `pending_live`：只准备材料，未请求模型。
- `blocked_model_config` / `blocked_vision_config` / `blocked_missing_image`：前置条件不足，未进行对应模型调用。
- `execution_failed`：调用、Schema 或安全校验失败；只记录异常类别，不回显服务商原始错误。
- `automatic_checks_failed`：已取得合法候选，但至少一项自动检查不符。
- `generated_pending_manual`：自动检查通过，**人工验收仍未完成**。

真实测试后，应逐条查看 `output` 与人工核对清单，记录通过、不通过、理由及修改建议。先脱敏再将必要摘要补到 `MODEL_VALIDATION.md` 和汇报页。首次各一次仅是五个样例的冒烟测试，不代表多轮稳定性或泛化准确率。
