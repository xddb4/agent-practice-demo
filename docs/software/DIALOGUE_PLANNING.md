# 对话规划与能力证据闭环

## 1. 先阅读回答，再查看近期任务

首次生成后回到已保存的对话；后续回复也保留在聊天中，不自动打开准备方案。
回答说明已知依据、不确定之处、长期方向和近期取舍，不展示内部逐步推理。
回答末尾的“查看近期任务与调整”打开最新方案和待确认变更，侧栏也保留入口。
有待确认改动时，可确认，或放弃建议继续聊。

任务生成规则优先细化未来七天，通常三至五项，由预算及任务特点决定，
不强行凑数；16 项仍是生成容量的安全限制。此范围由模型遵循提示词，
不是后端强制裁掉第六项，也不保证每次恰好五项。

## 2. 短名称与独立执行说明

`title` 通常使用8至24字的材料/对象与动作；`description` 保存材料选择、
步骤和范围。说明可在准备方案编辑，采纳后在日程详情查看。
后续对话可分别修改名称和说明。历史任务不自动截断或批量重写。

## 3. 每轮读取最新已确认记录

后续对话从当前账号状态读取已接受证据，按主题词匹配排序，最多12条、
6000字符。它是有边界的词面检索，不是语义向量检索；上下文标明遗漏与
局限。待确认、拒绝和待观察记录不传入。能力报告与 Agent 使用相同的已接受
证据来源，而非互相生成结论。生成期间相关证据变化会要求重新发送。

## 4. 对话反馈到证据收件箱

后续对话可返回最多三条候选，必须逐字引用本轮用户消息，并归入现有六维
科研素养框架。明确区分用户自述与用户报告的过程/成果；二者都未独立验证。
时间预算、偏好、目标、采纳任务、单纯完成勾选和模型推测不应作为能力证据。
不适合科研维度的英语学习反馈保留在学习情况摘要，不强行映射或生成英语评分。

用户点击“核对并保存”，编辑标题、正文、说明和维度，提交后进入待确认
证据收件箱；在那里接受后才纳入能力报告及后续 Agent 参考。保存来源方案、
回复标识和用户原话。同一候选重复提交不会重复写入。已归档候选所在轮次不
提供撤回，以保留来源；证据仍可通过收件箱及已处理证据管理。
